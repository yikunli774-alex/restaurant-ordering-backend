# Devlog — 2026-08-06

## 后厨看板 + 订单状态机的另一半(店家侧闭环)

### 意图
之前 `order_round` 只能停在 `CONFIRMED`;这一步让后厨把它推进完整状态机,顺路补上库存释放和菜品详情。

### 状态机(每步转移都是 CAS)
```
CONFIRMED →(prepare)→ PREPARING →(ready)→ READY →(complete)→ COMPLETED
     └────────────(cancel, 任意非终态)────────────→ CANCELLED(退库存)
```
每步 = `UPDATE order_round SET status = ? WHERE id = ? AND status = 上一态`。两个后厨同时点同一单也只有一个生效(其余 rows=0 → 409 非法转移)。和结账、开会话同一套并发手段。

### 写了什么
- `kitchen/KitchenRepository | KitchenService | KitchenController`:`GET /kitchen/orders`(队列,含桌号+菜品)+ `prepare / ready / complete / cancel`。
- 每个接口按**细粒度权限**保护(`order:read / order:prepare / order:ready / order:complete / order:cancel`)——V2 早就种下的权限终于用上,RBAC 从"设计"变"跑起来"。
- `InventoryRepository.release`:`reserve` 的镜像(reserved→available),取消轮次时退库存 —— **库存生命周期闭环**(补上了之前 flag 的缺口)。
- `V7` 迁移:`menu_item` 加 `description` / `image_url`(图片真实放对象存储 OSS/S3,库里只存 URL)+ 新权限 `order:cancel`。因为加了权限,RBAC 数从 8/5 → 9/6,同步改了断言。
- 菜品详情:`GET /menu-items/{id}`;列表也带上 `imageUrl`(缩略图)。

### 验证 ✅(53 个测试全绿)
`KitchenIntegrationTest` 5 条:队列看到来单 → prepare/ready/complete 逐步推进 → 完成后出队;跳状态 409;取消退库存(98→100);顾客/未登录访问后厨 → 403/401。
