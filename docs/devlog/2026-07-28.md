## 三、方案怎么改的(最关键的一次改动)

仓库里原本已有一份设计 `specs/2026-07-13-...`,它是「**一桌一张订单、下单即锁死购物车、订单级支付**」。
这跑不了「加菜」。所以我新写了一份**附录**(不覆盖原文,冲突以附录为准):

📄 `docs/superpowers/specs/2026-07-28-dine-in-multi-round-addendum.md`

核心变化:

- **订单(order)从「一桌唯一」降级成「一轮/一张来单(round)」** —— 一个桌台会话(session)下可以挂很多轮。
- **购物车从「永久冻结」改成「每轮提交后清空复用」** —— 只有点了「结账」才锁住。
- **支付从「订单级」上移到「账单级」** —— 账单 = 这桌所有未取消轮次的金额之和,离桌前付一次。
- 多出两个真实又好玩的**并发场景**:①「结账」用 CAS 抢锁,多人同时点结账只有一个成功;②「加菜 vs 结账」竞态,结账进行中不许再加菜。

会话状态机(改后):
```
OPEN ──(提交一轮, 可多次)────────> OPEN
OPEN ──(结账 CAS)────────────────> PENDING_PAYMENT
PENDING_PAYMENT ──(支付成功)─────> CLOSED
PENDING_PAYMENT ──(失败/超时/撤销)> OPEN
OPEN|PENDING_PAYMENT ──(店员强关)─> FORCE_CLOSED
```

### 几个学习者该知道的概念

- **Flyway**:数据库版本管理工具。你把每次表结构变更写成 `V1__xxx.sql`、`V2__xxx.sql`,它按顺序执行并记在 `flyway_schema_history` 表里,保证任何一台机器从空库都能重建出一模一样的结构。
- **Testcontainers**:测试时用 Docker 现起一个**真** MySQL 容器,测完销毁。
- **为什么不用 H2(内存数据库)测**:我们要验证 MySQL **特有**的行为(生成列、唯一索引对 NULL 的处理等),H2 装不像,测了等于没测。

在 Task 2 的地基上加了三样(细节见提交 diff):

- **统一错误响应(Problem Details / RFC 9457)**:任何接口出错都返回同一种 JSON——带 HTTP 状态、稳定错误码(如 `VALIDATION_FAILED`)、追踪 ID。由全局异常处理器 `GlobalExceptionHandler` 统一产出,业务代码不用各写各的。

## 八、Task 4 完成:打包成镜像、同时跑两份、Nginx 分流

### 这一步到底在干嘛(大白话)
到 Task 3 为止,程序只能在「你这台电脑 + 你手动装好的环境」里跑。Task 4 做两件事:
1. 把程序连同运行环境**打包成一个「镜像」**,任何装了 Docker 的机器一条命令就能跑。
2. 让同一个程序**同时跑两份**(app-1、app-2),前面架 **Nginx** 把请求轮流分给它们。为什么要两份?这个项目的卖点是「并发正确」——只有证明「即使跑在多个独立实例上也不会算错账、不会重复下单」,结论才成立。两实例就是这个证明的舞台,也是后面压测的基础。

### Docker 概念,从零讲
- **镜像(image)**:打包好的、只读的「程序+环境」模板,像一张系统安装光盘。
- **容器(container)**:用镜像跑起来的运行实例,像用光盘装出来、正在运行的一台虚拟小电脑。一个镜像能跑出多个容器(我们跑了两个 app 容器)。
- **Dockerfile**:写「怎么做这张光盘」的步骤清单。
- **docker compose / `compose.yaml`**:一键起一堆容器并把它们连起来的编排工具。
- **健康检查(healthcheck)**:compose 每隔几秒敲一下容器的健康接口,「谁健康了」才启动依赖它的下一个(MySQL 健康 → 启动 app;两个 app 健康 → 启动 Nginx)。
- **Nginx / 负载均衡**:门口分流员,请求按「谁当前更闲」轮流发给 app-1/app-2。
- **数据卷(volume)**:容器删了数据就没了;给 MySQL 挂数据卷 `mysql-data`,让数据库文件存在容器之外,重启不丢。

### 写了哪些文件
`Dockerfile`(打包配方)、`.dockerignore`(打包时排除哪些)、`.env.example`(密码模板,真 `.env` 不入库)、`application-docker.yml`(docker 里数据库地址改成容器名 `mysql`)、`compose.yaml`(一键起整套)、`deploy/nginx/nginx.conf`(分流规则)、`scripts/smoke-test.sh`(起来后自动验活)。

### 踩的两个坑(重点,值得记住)
1. **中文路径搞坏了 Docker 新版构建器。**
   报错:`x-docker-expose-session-sharedkey contains value with non-printable ASCII characters`。
   原因:新构建器(BuildKit)拿项目路径 `.../点单系统` 算一个「会话密钥」塞进网络请求头,而请求头只能是 ASCII,中文把它搞坏了。
   解决:用老构建器 `DOCKER_BUILDKIT=0 docker build`,不走那套机制。**这台机器以后所有 docker 构建都得这样。**

2. **两段式构建太慢 → 改成「本机打 jar,Docker 只封装」。**
   原本 Dockerfile 想在容器里从零编译(含重下所有 Maven 依赖)。但容器里没有你电脑上已缓存的依赖,加上老构建器用不了构建缓存,每次都重下几百个包,卡了十几分钟。
   解决:让 Maven 在**本机**打好 jar(依赖已缓存,几十秒),Docker 只把这个 jar 塞进精简 JRE,快了几十倍。
   代价:镜像不再「完全自包含」(部署前先 `./mvnw package`)。这是常见的正规做法(CI 打包 → Docker 封装),对我们够用;完全自包含的多段构建以后可在 CI 里用纯英文路径恢复。

### 验证 ✅
`docker compose up -d` 后:mysql / app-1 / app-2 全部 healthy,nginx 启动;`./scripts/smoke-test.sh` 通过。可打开 http://localhost:8080/swagger-ui.html 看 API 文档。

### 常用命令
- 停(保留数据库数据):`docker compose down`
- 起:`docker compose up -d`
- 改了代码要重来:`./mvnw -DskipTests package && DOCKER_BUILDKIT=0 docker build -t restaurant-ordering-backend:local . && docker compose up -d`

## 十一、业务 ①:登录鉴权的数据底子(RBAC)

进入业务模块,第一站是「鉴权」——分**认证**(你是谁,登录)和**授权**(你能干什么,权限)。这一小步先把「授权」的数据结构搭好。

**RBAC(基于角色的访问控制)**:不逐人配权限,而是「角色 ←→ 权限」「人 ←→ 角色」两层多对多。改权限只改角色,不用动每个人。

**V2 迁移建了 5 张表**:
- `staff_account`:店员账号(用户名唯一、密码哈希、状态、失败次数、锁定到期时间——后面登录限流/锁号要用)
- `role`:角色(KITCHEN 后厨、MANAGER 店长)
- `permission`:权限(`order:read` 看单、`order:prepare` 开始做…`menu:manage` 管菜单 等 8 个)
- `staff_role`:人 ↔ 角色(多对多关系表)
- `role_permission`:角色 ↔ 权限(多对多关系表)

并灌入种子:KITCHEN 拿 5 个操作权限,MANAGER 拿全部 8 个。**先不建具体账号**——第一个店长账号留到下一步接上 Spring Security、能正确加密密码时再建。

**测试**:`StaffRbacMigrationIntegrationTest` 断言 MANAGER=8、KITCHEN=5 个权限 → 通过。

**下一步**:接 Spring Security,做「密码登录 + 建第一个店长账号 + 按权限保护接口」。

## 十二、业务 ①(续):Spring Security 密码登录

给 RBAC 数据接上「真正能登录」的一层。

### 概念(从零)
- **密码哈希 / BCrypt**:密码不存原文,存单向加密结果;核对时把输入再哈希比对。库泄露也拿不到原密码。BCrypt 故意算得慢,防暴力破解。
- **JWT(电子通行证)**:登录成功发一段**签名**字符串,内含「你是谁 + 权限 + 到期」。之后每次请求带 `Authorization: Bearer <token>`,服务器验签即认人,不必查库、不必在服务器存会话(**无状态**)。
- **Spring Security 过滤链**:一道门卫。`login` 公开,其余要带有效通行证;通行证里的 `authorities` 映射成框架能检查的权限。

### 写了什么
- `common/config/SecurityConfig`:密码编码器(BCrypt)、JWT 签发/验签(HS256 + 密钥)、过滤链(放行 login/健康/文档,其余需登录)、`authorities` 声明 → 权限的映射。
- `staff/StaffRepository`:用 JdbcTemplate 查账号、查某人全部权限(权限码 + `ROLE_角色`)。
- `staff/StaffAuthService`:核对用户名+密码(**账号不存在与密码错返回同一个错误**,避免暴露哪些用户名存在),签发 15 分钟有效的 JWT。
- `staff/StaffAuthController`:`POST /staff/auth/login`(发通行证)、`GET /staff/me`(受保护,回显 id + 权限)。
- `staff/StaffBootstrap`:启动时若无账号,自动建 `manager`(密码走同一套哈希)+ MANAGER 角色,解决「第一个管理员」问题;多实例同时启动也安全(唯一约束 + 捕获重复)。

### 踩坑
`@WebMvcTest` 加了 Spring Security 后会拦住测试用的假接口。我先用 `addFilters=false` 关掉全部过滤器——结果**连自己的 `TraceIdFilter` 也关了**,`X-Trace-Id` 头没了、测试挂。改成**只排除 Spring Security 的自动配置**(保留 TraceIdFilter)后通过。

### 验证 ✅
`./mvnw test` → **9 个测试全绿**。`StaffAuthIntegrationTest`:登录拿 token → 带 token 访问 `/me` 得到 `menu:manage`、`ROLE_MANAGER` → 密码错 401 + `STAFF_CREDENTIALS_INVALID` → 无 token 401。

`manager` / `manager123`。生产用环境变量 `BOOTSTRAP_MANAGER_PASSWORD`、`JWT_SECRET` 覆盖。

## 十三、业务 ①(再续):Redis 服务端会话 + 即时吊销

给登录接上「能立刻作废通行证」的能力。

### 为什么(JWT 的软肋)
纯 JWT 一旦发出,到期前服务器无法作废——它不保存 token,只验签名。用户登出/被停用/改权限后,旧 token 仍能用到过期。安全硬伤。

### 怎么解决
- 登录时在 **Redis** 存一条会话(谁 + 权限);token 里**只放会话号 `sid`**,不再放权限。
- 每次请求验签后,再查 Redis 会话在不在——不在就拒(**fail closed**);权限也从会话读(改角色能立刻生效)。
- **登出 = 删会话**,旧 token 立刻失效。
- **Redis**:内存数据库,读写微秒级,天生支持过期与秒删,最适合这种数据。

### 写了什么
- `staff/StaffSessionStore`(Redis):`create`(存会话 + TTL)、`find`、`delete`。
- `staff/StaffJwtAuthenticationConverter`:验签后查 Redis 会话;没有就抛 401;有就用会话里的权限构造身份。**故意不做成 @Component**(见踩坑)。
- `common/config/SecurityConfig`:手动 new 出上面的转换器接进过滤链。
- `staff/StaffAuthService`:登录开会话、token 只带 `sid`;`logout(sid)` 删会话。
- `staff/StaffAuthController`:新增 `POST /staff/auth/logout`;`/me` 改为从「当前身份」读权限。
- Redis 基建:依赖、`application.yml`/`application-docker.yml` 配置、`compose.yaml` 加 redis 服务 + 依赖健康、测试用 Testcontainers 起真 Redis。

### 踩坑
`@WebMvcTest`(只测 Web 的轻量切片)会**自动加载所有 `Converter` 类型的 bean**。我的转换器实现了 `Converter` 又标了 `@Component`,于是切片测试也去实例化它、拉出 Redis 依赖 → 上下文炸。修法:去掉 `@Component`,改由 `SecurityConfig` 手动构造——切片测试就不碰它了。

### 验证 ✅
`./mvnw test` → **10 个全绿**。关键新测试 `logoutRevokesTheSessionImmediately`:登录 → `/me` 通 → 登出(204)→ **同一个未过期、签名仍有效的 token 再访问 `/me` 直接 401**。即时吊销成立。

### 本模块还剩(可选)
刷新令牌轮换、登录限流 + 失败锁号、改角色/停用时吊销该用户全部会话。
