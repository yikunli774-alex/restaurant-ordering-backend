## 二、顾客侧 ①:桌台 + 会话 + 参与者(数据模型)

### 概念(从零)
- **桌台 `dining_table`**:一张桌子,固定编号(T01),贴二维码。
- **会话 `table_session`**:一拨客人从坐下到结账 = 一个会话。**同桌同时只能有一个「进行中」会话**,否则两拨客人账目会混。顾客侧最关键的规则。
- **参与者 `participant`**:扫码进来的匿名顾客,发 token(只存哈希),同桌多人共享一个会话。

### 关键技巧:用「生成列 + 唯一索引」把铁律焊死在数据库里
会话表加一个**自动计算**的列 `active_table_id`:
```sql
active_table_id ... GENERATED ALWAYS AS (
  CASE WHEN status IN ('OPEN','PENDING_PAYMENT') THEN dining_table_id ELSE NULL END
) STORED,
CONSTRAINT uk_table_session_active UNIQUE (active_table_id)
```
- 会话进行中 → 这列 = 桌号;结束 → = NULL。
- MySQL 唯一索引**允许多个 NULL、但不允许两个相同的非 NULL**。
- 于是:同一桌的「进行中会话」最多一个;历史已结束会话(NULL)随便多少张。
- **好处**:这条规则由**数据库本身**保证——并发下(多个请求同时想在一张桌子开会话)也只有一个能成功,应用层不用加锁。这是后面并发正确性故事的地基。
